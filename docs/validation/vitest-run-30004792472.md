## What the validation found

The original line-by-line spike selected the runner's Azure region as the first
difference. That was observable but not the decision-relevant failure evidence.

The comparison now prioritizes the earliest failure signal that does not exist
in the passed log. For this pair it selects the failed test summary and returns
the successful test summary as counterpart evidence.

## Adapter finding

`gh run view --job <old-attempt-job-id> --log` returned the latest attempt's log
for both job IDs in this case. The two downloads were byte-identical. Direct
job-log API endpoints returned distinct failed and passed logs. A future GitHub
adapter must therefore verify downloaded job metadata and content instead of
assuming the CLI output belongs to the requested historical attempt.
